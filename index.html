Quick start

Find a healthy XDC Mainnet RPC endpoint right now. Add ?pretty to any live URL to read it in a browser.

curl -s RPC_HEALTH_URL \
  | jq -r '.networks[] | select(.network=="mainnet") | .recommended[0]'
import json, urllib.request

url = "RPC_HEALTH_URL"
data = json.load(urllib.request.urlopen(url))
mainnet = next(n for n in data["networks"] if n["network"] == "mainnet")
print("Use:", mainnet["recommended"][0])
for e in mainnet["endpoints"]:
    print(f'{e["status"]:9} {e["uptime_24h_pct"]}%  {e["url"]}')
const res = await fetch("RPC_HEALTH_URL");
const data = await res.json();
const mainnet = data.networks.find(n => n.network === "mainnet");
console.log("Use:", mainnet.recommended[0]);

// Is the data fresh?
const age = (Date.now() - Date.parse(data.generated_at)) / 1000;
if (age > data.stale_after_seconds) console.warn("Feed looks stale");

Conventions

  • Freshness. Every file has generated_at, update_interval_seconds and stale_after_seconds. If the data is older than that, don't trust it.
  • Amounts. Token amounts are exact integer wei as strings in *_wei fields (1 XDC = 1018 wei). The *_xdc numbers are rounded, for display only.
  • Addresses. Lowercase 0x… hex. Swap 0x for xdc to get the XDC-style form.
  • Times. ISO 8601 in UTC, ending in Z.
  • Versions. Paths start with /v1/. Within v1, fields are only ever added; anything breaking gets /v2/. Changes are listed in v1/changes.json.
  • History. One NDJSON file per UTC day (one JSON object per line), listed in each dataset's history/index.json.

Good to know

  • Rewards are measured, not reported. XDC adds epoch rewards straight to balances in the first block of each epoch (90 % to the node's owner, 10 % to the foundation). Each owner's reward is their balance change across that block, less their own transactions, any block fees and any XDC moved to or from them by contracts (such as a stake withdrawal). A figure that can't be fully explained is marked unverified and kept out of every total. Rewards paid at the start of epoch N are for epoch N−2.
  • Owners, not nodes. An owner with several masternodes gets one combined figure. Each epoch's typical node reward (from owners running a single node) shows what each owner should have received, so vs_typical and shortfall_nodes reveal under-performing setups.
  • Is a node online? Validators carry the last block each node signed, and not_signing_recently flags a masternode that hasn't signed for about an hour.
  • For accounts. Daily owner totals in XDC as JSON and CSV, plus a CSV per month. Any epoch left out of a total as unverified is listed beside it. Apply your own price source for fiat values.
  • Alerts for your nodes. events reports each change once: slashing, status changes, nodes that stop signing, unpaid owners and RPC outages. Every owner address has its own Atom feed of just its nodes' events, to follow in any feed reader with notifications (or everything in one feed). Enter your owner or masternode address:

    Our feeds and alerts never ask you to click a link, sign in, sign a transaction or send anything; treat any message that does as fake.
  • For AI assistants. The XDC Open Data MCP server lets Claude and other assistants query all of this directly.
  • Fair use and fallback. Poll no faster than each dataset's update interval and cache what you fetch. If a live URL is unreachable, use the hourly.json copies on this site, which are refreshed every hour.
  • Not advice. Information only. No personal data is published.
